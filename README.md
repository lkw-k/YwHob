# YwHob(축전 CCTV 혼잡도 측정 시스템)
해당 프로젝트는 ai 축전에서 사용될 모델을 만들게 될 프로젝트 입니다.

CCTV를 주기적으로 캡처해 구역별 혼잡도를 산출하고, 수치와 블러 이미지를 웹 서버로 전달한다.

**담당 범위**: 영상 수신 → 캡처 → 인원 추정 → 혼잡도 산출 → 블러 → 웹 전달

## 계획 상황

| 항목 | 내용 |
|---|---|
| 행사 규모 | 박람회, 예상 1만 명 |
| 카메라 높이 | 최소 2층, 더 높을 수 있음 (미확정) |
| 카메라 대수 | 미확정 |
| 실행 환경 | 노트북 1대, 다중 카메라 |
| 측정 주기 | 30초 |
| 샘플링 | 주기당 3초간 5장 |
| 출력 | 혼잡 3단계 + 연속 점수 + 블러 이미지 |
| 모델 | 미정 (경량 + 파인튜닝 전제) |

## 파이프라인

```
캡처(3초/5장) → 머리 검출 → 중앙값 집계 → EMA 스무딩 → 3단계 판정 → 블러 → 전송
```

| 단계 | 설계 |
|---|---|
| 캡처 | 원본은 메모리에만 유지. 카메라별 캡처 시점 분산 |
| 검출 | 머리 단위 (전신은 가림에 취약) |
| 집계 | 5장 중앙값. 평균 아님 |
| 신뢰도 | 5장 간 편차로 산출. 임계 초과 시 주기 폐기, 직전 값 유지 |
| 스무딩 | 최근 3~5주기 EMA |
| 판정 | 히스테리시스 적용 (상승/하강 임계값 분리) |

5장을 뽑는 이유는 이동 추적이 아니라 측정 노이즈 제거.

## 핵심 제약

### 처리량

30초 중 캡처는 3초이므로 배치 처리 구조로 설계. 실시간 스트림보다 훨씬 많은 카메라 수용 가능하도록 계획.

```
필요 처리량 = 카메라 수 × 5장 / 30초
가용 시간   = 30초 - 캡처 3초 - 전송/여유
```

- 캡처 시점 stagger로 순간 부하 분산
- 5장 배치 추론
- 캡처/추론/블러/전송 비동기 분리

```
해상도 ↓ → 속도 ↑ , 원거리 머리 소실 → 과소 추정
해상도 ↑ → 정확도 ↑ , 카메라 수 제약
```

검출 실패가 "사람 없음"으로 집계되는 게 위험. 검출 가능한 최소 머리 크기를 먼저 실측하고 마스킹 경계를 정한다.

### 모델

- 경량 계열 (YOLO nano/small 급)
- COCO 사전학습은 person만 있어 머리 검출 부적합 → 파인튜닝 필요
- 데이터 후보: CrowdHuman(head), SCUT-HEAD, 현장 샘플 자체 라벨링
- 최적화: ONNX 변환, 양자화, 배치 추론

## 구역 설계

카메라 1대 ≠ 구역 1개. 화면 내 ROI 단위로 분할한다.

- 근거리/원거리는 원근 차이가 커서 별도 구역
- 신뢰도 낮은 원거리는 마스킹 제외
- 부스 배치 기준 물리 구역과 ROI 매핑

임계값은 카메라별 상대 캘리브레이션으로 결정. 높이·각도·시야 면적이 달라 공통 공식 적용 불가.

## 개인정보 처리

목적은 개인정보 보호.

- 원본은 저장·전송하지 않고 로컬에서 블러 후 즉시 폐기
- **블러 실패 시 이미지 미전송** (수치만 전송)

| 항목 | 방향 |
|---|---|
| 방식 | 전체 균일 블러. 선택적 얼굴 블러는 검출 실패 시 원본 노출 |
| 강도 | 다운스케일 후 블러 시 복원 불가 |
| 대상 | 중앙값 채택된 1장만 |
| 보관 | 서버 측 보관 기간 정의 필요 |

## 인터페이스

Redis에 최신 값 덮어쓰기 → 웹 서버가 읽기. 양측 장애 전파 차단.

```json
{
  "zone_id": "hall_a_front",
  "level": 2,
  "score": 0.41,
  "confidence": "high",
  "image_url": "/snapshots/hall_a_front.jpg",
  "updated_at": "2026-09-20T14:30:00+09:00",
  "status": "ok"
}
```

| 필드 | 목적 |
|---|---|
| `level` | 혼잡 3단계 (0/1/2) |
| `score` | 연속값. 그라데이션 표현 및 임계값 재조정용 |
| `confidence` | 5장 편차 기반 |
| `status` | 카메라 장애를 "여유"로 오인 방지. 90초 미갱신 시 `stale` |
| `image_url` | 이미지는 JSON에 인코딩하지 않고 URL만 전달 |

30초 주기이므로 폴링으로 충분. 푸시 필요 시 SSE.

## 진행 순서
현재 미정.

## 미결 사항

- 카메라 대수, 위치, 실제 높이
- 모델 선정
- 수용 가능 카메라 수
- 블러 강도 기준, 이미지 보관 정책
- 주최 측 개인정보 요구사항
